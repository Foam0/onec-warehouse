## Воспроизведение

Из корня репозитория:

```bash
python3 scripts/check_metadata.py
oscript tests/run.os
mkdir -p reports
java -jar /path/to/bsl-language-server-1.0.7-exec.jar analyze -s src -o reports -r json
python3 scripts/check_bsl_report.py reports/bsl-json.json
```

Для Java нужен JDK 21+. CI использует закреплённые версии инструментов и проверяет SHA-256 архивов.
Текущий результат удалённого запуска смотрите на вкладке Actions; локальный результат не подменяет статус CI.

## Пределы статического анализа

BSL LS запускается без справки установленной платформы. Проверка разбора модулей не подтверждает
существование каждого платформенного метода, исполнение запросов и импорт XML в Конфигураторе.
Python-проверка метаданных контролирует ссылки и комплектность, но не является проверкой по XSD платформы.

Предупреждения: `IsInRoleMethod, UnusedLocalVariable, UsingFindElementByString`. Роли используются именно как бизнес-полномочия процесса.
Поиск демоэлементов по коду используется только при наполнении учебной базы. Вызовы привилегированного
модуля требуют ручной проверки границы полномочий; они не доступны клиенту напрямую.

В исходниках явно отмечены локальные исключения диагностики: тестовые транзакции откатываются даже
при успешном сценарии; обработчики не пропускают проверки при `ОбменДанными.Загрузка`, потому что обмен
не реализован. Складской контроль намеренно читает все текущие остатки, включая старые измерения.

## Проверки перед показом работающей базы

Загрузить исходники в новую ИБ, проверить конфигурацию, обновить БД и войти под созданным пользователем.
Запустить сценарии обработки «Демонстрация». Проверить результаты отчётов. Во втором проекте пройти
маршрут отдельными бизнес-пользователями и проверить запрет самосогласования. Открыть два сеанса
и воспроизвести одновременный расход или переход с одной ожидаемой версией. Сохранить реальные результаты
и скриншоты только после исполнения этих шагов.
